# Review-stage manufacturing generator

Run with KiCad 10's bundled Python and a frozen candidate directory:

```sh
/Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/3.9/bin/python3.9 \
  analysis/v1_1_release_20261012/manufacturing/generate.py \
  --candidate /absolute/path/to/candidate \
  --output /absolute/path/to/new-review-output
```

The output folder must be new and outside the source. Native KiCad exports produce both copper, paste, mask and silk faces, Edge.Cuts, separate PTH/NPTH drills and Gerber job. The generator writes BOM/CPL, untouched native position CSV/netlist, per-reference identity/placement audit, actual mask coverage proof, fabrication-review ZIP and SHA-256 manifest. It never saves source CAD, uploads, or orders. Its input manifest covers the schematic/board/project/rules, library tables and project-local libraries/models; editor history, lock/UI state and release documentation are not fabrication inputs. Interpreter caches (`__pycache__`, `.pyc`, `.pyo`) and `.DS_Store` are excluded.

The canonical `hardware/gerbers/v1.1-pilot` export contains 56 assembly references and 10 exclusions. The first post-export correction removed two Python-cache entries from the manifest's source list; at that stage all 27 other package files remained byte-identical. `cache-input-scope-correction.json` records that limited operation. A later, separately recorded supplier-rotation correction updates the CPL and its audit/documentation. The final manifest pins 160 CAD inputs and 28 outputs, retaining the original export commands and generator provenance alongside the explicit post-export correction.

Part selection is checked against the actual prior JLC selected-parts UI text in `../jlc/previous-selected-parts.txt`, not stale descriptions in the old BOM. PCB and schematic must agree on explicit `Supplier Part` and `Manufacturer_Part_Number`. A changed original part requires `--allow-part-change REF`; unused allowances fail. New refs need explicit supplier identity and either a centered SMD footprint or explicit footprint-local `Placement Offset X` / `Placement Offset Y` in millimeters. The same explicit offsets must be reviewed with the supplier's component preview. Manual AE1/AE2/J1/J2/J3/J4/C5/J20 and mechanical/DNP/excluded native features are omitted. A reference excluded from just one of BOM/placement fails. BOM and CPL are exactly one row per assembly ref.

Placement is independently anchored to the unchanged historical PCB and **repository v1 production input CPL** hashes. The generator recreates the historical PCB directly from Git commit `9bdd19ec707455271f48f5a5d8be352fc696cf9c` and validates its original audit hash; it does not require the untracked historical audit snapshot. All 53 historical selected nonmicrophone references reproduce that input file's center/rotation using **placement-side SMD copper-pad bounds**, with all text, graphics, 3D models and through-hole thermal vias excluded. This is essential: U2's anchor is 72.715,64.660 mm while its historical SMD-pad center is 64.950,72.205 mm. Generic KiCad `GetCenter()` is unsuitable for other packages because extra drawing geometry biases U1/U3/U7/L1. Bottom baseline angles follow `(180 - native angle) mod 360`; top angles follow the native angle. This proves the old input convention only. **The repository CPL is not a verified JLC post-CAM adjusted file, and neither old nor new supplier models inherit validated rotation from that equality.** Earlier reports using “shipped convention” retain their numeric evidence but that interpretation is superseded here. The actual JLC preview exposed orientation corrections that the historical equality cannot establish.

For explicit preview-tested corrections, add `--supplier-rotation-profile /absolute/path/to/profile.json` to the command. The JSON is a direct reference mapping. Each reference maps to exactly three fields: `rotation_deg` (the **absolute final CPL angle**, finite and in `[0,360)`, at most six decimals), `evidence` (a nonempty saved preview/capture reference), and `reason` (a nonempty explanation of the observed correction). Do not encode a relative clockwise/counterclockwise delta or assume the UI rotation sign equals the CPL sign. The final absolute numeric value must come from the reviewed supplier workflow.

The parser rejects duplicate keys, unknown fields, malformed/nonfinite angles, missing evidence/reason and any reference absent from automated assembly—including manual/DNP parts. It preserves the historical proof, native position CSV, centers, board side, population, BOM and CAD. Only the selected CPL `Rotation` values change. Both assembly audit and manifest record original versus absolute override angle, exact part identity, location, evidence, reason and baseline provenance. The exact profile is copied into the output, hashed as evidence, and checked for mutation during export. Profile evidence strings identify the human-reviewed record; the generator does not itself inspect or certify the referenced image.

The pilot package now contains the reviewed absolute rotations **U1 90°, U4 270°, U7 0°, U8 90°**. A fresh scratch export with the profile proved its CPL byte-identical to the reimported supplier probe. `apply_supplier_rotations.py` then applied only the CPL/audit/documentation/profile correction to the existing package; all 24 retained outputs, including BOM, native exports, fabrication ZIP, Gerbers and drills, stayed byte-identical. Original files and the correction report are preserved in [rotation-correction-before](rotation-correction-before/correction-report.json). No CAD or fabrication artwork was re-exported as part of that scoped correction. The final package BOM/CPL was reimported to the JLC draft, with all 53 available placements selected; R4/U2/U6 and complete supplier approval remain pending. See [final import evidence](../jlc/final-package-import-selection.json).

No solder mask is permitted on either face. The generator rejects a mask file without a negative-file-polarity, dark full rectangle covering the board outline and every native copper island, with positive edge overrun and no clear-polarity operation. The Gerber job must specify zero thickness on both mask layers. Blank mask files do not pass. The supplier order must explicitly select/confirm no mask both sides and no tenting.

Validation: the metadata-only trial exports 51 assembly refs, 10 exclusions and the three already removed refs C13/MK1/R20. It preserves every source hash. Trial files here are historical generator validation, **not the final payload release**. Negative checks intentionally remove supplier metadata, duplicate a ref, remove the whole-face mask opening, and mismatch BOM/placement exclusion. See the JSON evidence.

`review_u7_paste.py` independently reads actual exported RoundRect macros and U7 flashes. Snapshot c1394009… gives 12 paste apertures aligned to 12 copper pads. Each aperture is 0.315 × 0.405 mm with 0.04725 mm corner radius, versus 0.350 × 0.450 mm copper with 0.0525 mm radius: exactly 90% linear size and 81% area. The actual aperture area is 0.12565855 mm²; area/perimeter/stencil-thickness is 0.92472 at 0.10 mm. This is geometric evidence only. No global reduction is applied; supplier stencil decisions must not double-reduce the local U7 aperture change. The [final integrated paste proof](final-u7-paste-proof.json) also passes PCB `490af47db22ef076938c17319782f194623d8f8b6a3f864a2e0cc23b3d025b15`; repeat it if copper or paste geometry changes.

`freeze_new_footprints.py --candidate INPUT --output NEW_SCRATCH`, using the same bundled Python, runs **after power integration and before ERC cleanup**. It saves U8/R24/R25/R26/C22 as individual project-local footprints through native `FootprintSave`. The board stays byte-preserved except those library IDs; schematic changes are limited to their Footprint fields. Complete parsed-tree comparisons prove all pads, positions, nets, graphics, models and other metadata unchanged. Native library comparison must pass for every saved copy. An optional `--thermal-manifest FILE`, also passed to `merge_power.py`, re-freezes D3/J4 after exactly the reviewed pad-1 thermal gap/bridge overrides. It preserves J4's integrated elongated pad geometry. The manifest pins the reviewed PCB hash and both pad UUIDs; only absent-to-0.25 mm changes to `thermal_gap` and `thermal_bridge_width` are accepted.

The five-part helper trial preserved 66 footprints and 245 physical pads; native DRC reported no footprint-library mismatches and no schematic parity findings. That input was an earlier **unrouted** power snapshot, so the trial does not establish routing readiness. `footprint-freeze-trial.json` and `footprint-freeze-drc-review.json` record this limited result. `thermal-import-unit-review.json` records preservation of integrated D3/J4 geometry and rejection of a 0.30 mm override outside the author manifest. Final combined routing, ERC, connectivity and manufacturing checks remain separate release steps.
